## 实验 2：插件用 LrHttp 访问本机 Python 服务（2026-11-01，Lightroom Classic 15.2.0）

**做法**：`server/exp2_server.py`（标准库，只绑 `127.0.0.1:58770`，随机口令 + Host/Origin 检查）；插件菜单 `LrMCP: HTTP test (experiment 2)` 发 GET 请求。

| 测试 | 结果 |
|---|---|
| T1 口令正确 | ✅ 200，5 ms |
| T2 口令错误 | ✅ 401 |
| T3 带 Origin 头（模拟网页乱连） | ✅ 403 |
| T4 连续 10 次请求延迟 | ✅ 平均 1.5 ms，最差 8.5 ms |
| T5 服务端慢 3 秒、超时 10 秒 | ✅ 200，耗时 3003 ms（长轮询可行） |
| T6 服务端慢 5 秒、超时 2 秒 | ✅ `timedOut`，**实际约 4 秒才返回**（超时是「每个阶段」各算一次，实际约为设定值的 2 倍） |

**结论**：方案 B1（Python 本机 HTTP 服务 + 插件 LrHttp 请求）**在 Windows + LrC 15.2 上可行**，没有被系统代理干扰，延迟极低。

**LrHttp 实际发送的请求头**：`Accept`、`Authorization`、`Content-Type: text/plain`（除非自己指定）、`User-Agent: Adobe Photoshop Lightroom`、`Host`、`Cache-Control`；**不带 Origin**（我们测试时手动加的）。

**重要发现：Claude 桌面版的文件重定向（MSIX）**
- Claude 桌面版是商店（MSIX）应用，从它启动的程序（包括 Claude Code 的 shell、由它启动的 MCP 服务）往 `AppData\Local` 写的文件，会被重定向到 `AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\...`。
- 在它里面看得到文件，Lightroom 等外部程序看不到（`LrFileUtils.exists` = false）。
- **规则：插件与服务之间共享的文件（口令、端口）不能放在 AppData；用 `C:\Users\<用户>\LrMcp\`**（用户目录下，不在 AppData 内，实测可见）。HTTP 通信走网络，不受影响。
- Lightroom 里读文件：`io.open` 对非 AppData 路径可用；SDK 文档推荐 `LrFileUtils.readFile`/`exists`。`os.getenv` 不可用，用户目录用 `LrPathUtils.getStandardFilePath("home")`。

**待办/注意**：
- 只测了 GET；POST + JSON 正文待测（需显式指定 `Content-Type: application/json`）。
- 服务端要处理客户端超时断开（`BrokenPipe`），实验里被超时中断的请求没有写日志。
- 令牌文件的 ACL（仅当前用户可读）还没做。
- Origin 校验只是手动模拟，LrHttp 自己不带 Origin，浏览器带，所以规则成立。
