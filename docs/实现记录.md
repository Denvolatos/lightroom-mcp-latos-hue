## 与方案不同的地方 / 实现中发现的

1. **照片标识用 `uuid`**：官方有 `catalog:findPhotoByUuid`（方案里标「待验证」，已确认存在并可用）。
2. **`getTargetPhotos()` 在没有选中任何照片时返回整个胶片带**（官方文档写明）。`lr_list_selected` 先用 `getTargetPhoto()` 判断是否真有选中，否则返回空列表。
3. **Windows 上 Python 的 HTTP 服务默认可以多个进程共用端口**（`SO_REUSEADDR`），会让「单实例」规则失效。改用 `SO_EXCLUSIVEADDRUSE` 独占绑定，并有测试；停止后立刻重启同端口可行。
4. **`mcp` 2.x 只会把 `ToolError` 的文字交给模型**，其他异常会被换成一句泛泛的话。所有工具用 `_guard` 把我们的中文提示转成 `ToolError`。
5. **Claude 刚启动服务时插件可能还没连上**（插件没连上时每隔 ≤5 s 重试）。调用时最多等 6 s（`CONNECT_WAIT_SECONDS`）。
6. **官方文档里的键名拼写错误在 15.2 实际并不存在**：`HueAdjustmentMagenta`、`LuminanceAdjustmentAqua`、`ParametricLights` 都是对的（文档写成了 `Magenha`、`Aque`、`Parametriclights`）。
7. **`lrmcp register`** 通过 `claude mcp add --scope user` / `codex mcp add` 登记，不手改它们的配置文件；Claude 桌面版不自动登记（配置文件位置可能被 MSIX 重定向，待验证），安装后给出手动步骤。本机没有装 Codex，Codex 路径只做了单元测试。
8. 实验用的菜单脚本归档到 `experiments/lua/`；插件目录只剩产品代码 + 开发通道。
9. **中文 Windows 控制台是 GBK，打印 ✅/❌ 等符号会使程序崩溃**（`lrmcp register` 登记成功后在打印结果时崩了）。命令行输出统一走 `out()`：控制台编码装不下时自动换成 `[OK]`/`[X]`/`[-]`/`[i]`/`->`；有单元测试。MCP 工具（`lr_doctor`）返回给模型的文字不受影响（UTF-8）。
10. **已对用户的 Claude Code 实际登记**（用户级，命令指向 `build\dist\lrmcp\lrmcp.exe`，`claude mcp get` 显示 Connected）；在新会话里实际使用待用户试用。

# 🛠️ 0.2.0（路线图里的 v1.1：受保护的修改）实现记录

日期：2026-11-02。范围与方案见 `docs/方案.md` 第 10 节；实测依据见 `docs/实验记录.md` 的实验 4、5。

## 做了什么

- 新工具：`lr_set_develop`、`lr_restore`、`lr_restore_original`、`lr_list_edits`（共 9 个工具，5 个只读）。
- 可改：35 个滑块（曝光；对比度、高光、阴影、白色、黑色、纹理、清晰度、去朦胧、自然饱和度、饱和度；HSL 24 项）。范围：曝光 ±5，其余 ±100；**单次限幅**：曝光 ±1，其余 ±30（超过就拒绝，提示分几次改）。
- 写入前把旧值存到 `~/LrMcp/edits/<编号>.json`；还原 = 把旧值写回。读回核对（容差 1e-3），返回改前改后。
- 只读开关：`~/LrMcp/readonly` 文件或环境变量 `LRMCP_READONLY=1`，服务端和插件各自检查。
- 白名单在 `server/lightroom_mcp/edits.py`（Python）和 `plugin/.../Limits.lua`（Lua）各一份，**测试逐项比对两份必须一致**。

## 验证结果

| 项目 | 结果 |
|---|---|
| 单元测试 | ✅ 74 个（含 14 个用「假 SDK」在 Lua 5.1 里直接运行插件真实 `Commands.lua` 写入逻辑的测试，用可选依赖 `lupa`；没有 lupa 时自动跳过） |
| 真实 Lightroom 写入验收（`acceptance_write.py`，测试目录） | ✅ 20 项全过：改动读回一致；预览变化；限幅、越界、白平衡、白名单外参数都被**插件自己**拒绝且照片不变；只读开关服务端和插件都拒绝；还原后 Lightroom 报告的 **65 个值全部与开始时一致**，预览文件大小与基准相同（像素级一致） |
| 通过打包后的 `lrmcp.exe` 走真实 MCP 客户端（`smoke_stdio.py`，`SMOKE_WRITE=1`） | ✅ 9 个工具、读写标注正确；`lr_set_develop(preview=true)` 返回文字加图片；错误提示（白平衡被拒、+3 EV 被限幅）的中文原文传到模型；`lr_restore_original` 后回到原值 |

## 实现中发现 / 与方案的偏差

1. **Lightroom 的 `applyDevelopSettings` 不检查范围**（越界值原样存下），所以范围和限幅检查必须自己做（见实验 5）。
2. **修改记录的先后顺序**不能靠编号：编号只精确到秒、后缀随机，同一秒内连改两次顺序会乱，而「最初的值」取决于顺序。改用严格递增的 `created_ns`；有测试。
3. **口令文件被删后服务不自愈**（我的开发辅助脚本误删过一次）→ 服务每次被插件联系时检查并补回同一个口令；开发辅助 `server/dev_tools.ps1` 现在在端口被别的程序占用时拒绝运行，且只清理自己创建的文件。
4. **旧值先存盘再写入**：先读当前值存成 `pending` 记录，写入成功后再用插件读回的权威旧值更新；写入失败记 `failed`，进程中途崩溃也留有旧值。
5. **`restore` 不受单次限幅约束**（可以一步写回），但仍受白名单和范围约束。
6. 所选照片在第一步就解析成固定的 `uuid`，之后的步骤都用它（用户中途点了别的照片也不会改错）。
7. 版本号：公开版本按「加功能升中间位」从 0.1.0 升到 **0.2.0**（内部路线图称 v1.1）。
