# 📐 方案（v1.0 设计）

> 状态：草案，待用户确认。依据：调研 A–E（在 Claude code 工作区的 `学习与研究/04-代码脚本/Lightroom-MCP/调研/`）与本仓库 `docs/实验记录.md` 的实测结果（Windows + Lightroom Classic 15.2）。**写成「已验证」的都在实验里测过；没测的标「待验证」。**

## 1. 目标与边界

- 让 Claude / Codex 当「调色老师 + 修图助手」，帮用户修自己拍的照片。用户调色与编程基础为 0，所以：大白话、少操作、出错有中文提示。
- **v1.0 只看不改**：读照片信息、看预览、看直方图数字，让 AI 分析「这张哪里有问题」。**v1.0 没有任何写参数的工具**，所以不可能改坏照片。
- 只做 Windows + Lightroom Classic。朋友也能用（第二目标）：一键安装 + 中文自检。
- 非 Adobe 官方项目；Adobe SDK 文件与示例代码不进仓库。

## 2. 总体结构

```
Claude / Codex ──(MCP, stdio)──▶ Python 服务 lightroom_mcp
                                    │  同进程内开一个本机 HTTP 队列（127.0.0.1:58770）
                                    ▲
         Lightroom 插件（Lua）每 ≤10 s 用 LrHttp 来取任务、回结果
```

| 选择 | 理由（已实测） |
|---|---|
| Python 服务开 HTTP、**插件来取任务**（方案 B1） | 端口固定；插件重载不换端口；Python 重启自动恢复；延迟平均 1.5 ms；只绑 127.0.0.1 由我们自己保证 |
| LrSocket 双端口（B2） | 也可行（仅绑 127.0.0.1，3.4 ms），**作备选**；缺点：端口随机、每条消息必须以换行结尾 |
| 共享文件放 `C:\Users\<用户>\LrMcp\`，**不放 AppData** | Claude 桌面版是 MSIX 应用，它启动的程序写 AppData 会被重定向，Lightroom 读不到 |

**单实例**：同一时刻只允许一个 MCP 服务进程占用端口；第二个启动时给出中文提示「已有另一个 Lightroom MCP 在运行」（多会话共享以后再做）。

## 3. 安全

| 项目 | 做法 |
|---|---|
| 只在本机 | 绑 `127.0.0.1`（实测） |
| 口令 | 服务每次启动用 `secrets.token_urlsafe(32)` 生成，写入 `~/LrMcp/token`（用 `icacls` 限制为仅当前用户，**待实现**）；插件每次 401 后重读 |
| 防网页乱连 | 校验 `Host`；**带 `Origin` 头一律拒绝**（浏览器带、LrHttp 不带，实测）；不返回 CORS 头 |
| 插件只执行白名单命令 | 命令名固定；**路径不从请求里来**（预览只写固定目录）；数值有范围；不提供任意 Lua / 任意文件 / 任意命令 |
| 开发通道 | `DevLoop.lua`、`devscripts/`、`dev_bridge.py` 仅开发，**发布版不包含** |

## 4. v1.0 工具（MCP，全部只读，≤6 个）

| 工具 | 作用 | 返回 |
|---|---|---|
| `lr_status` | Lightroom 版本、当前目录名、插件版本、选中几张 | 文本 |
| `lr_list_selected` | 当前选中的照片（上限 20） | 文件名、格式（RAW/JPG）、评分/旗标、尺寸、拍摄参数（ISO、光圈、快门、焦距、镜头、机身、时间） |
| `lr_get_develop` | 读某张照片当前的调整参数 | 白名单键（曝光、对比度、高光、阴影、白色、黑色、清晰度、纹理、去朦胧、自然饱和度、饱和度、白平衡等）；注明 RAW 在未编辑时读不到 Temperature/Tint（实测） |
| `lr_get_preview` | 给 AI 看图 | 一张图（默认长边 1024、JPEG q=0.8、sRGB，约 0.5 s、约 300 KB）+ 直方图数字（亮度分布、过曝/欠曝比例、平均亮度、各通道均值，Python 用 Pillow 算，SDK 没有直方图接口） |
| `lr_doctor` | 自检并用中文说明哪步坏了 | 文本 |

- 照片用目录内编号（`localIdentifier`）标识；跨会话稳定性用 `uuid`（`catalog:findPhotoByUuid` 是否可用：待验证）。
- 预览由插件用 `LrExportSession` 导出到固定目录 `~/LrMcp/previews/`（不加入目录、不覆盖原图），Python 读取后返回图片，并清理超过 24 小时的旧文件。导出时 Lightroom 会闪一下进度条（实测）。
- 工具标注 `readOnlyHint`。工具少而稳，不为每个滑块一个工具。

## 5. 插件（Lua）

- 入口 `Info.lua` + `Init.lua`；`LrForceInitPlugin = true`（冷启动是否自动运行：**待验证**）；至少一个菜单项（官方要求）。
- 图库 → 增效工具附加功能里有「LrMCP：状态」，显示「已连接 / 未连接（Claude 没开）」。
- 命令循环：取任务 → 白名单分发 → 在异步任务里执行 → 回结果；所有 SDK 调用放在 `LrTasks.startAsyncTask` 内；会让出控制权的查询不嵌在读写门内（Automaat 在 Windows 的死锁经验）。
- 响应用一个很小的 Lua JSON 编码器（SDK 没有 JSON）；任务指令用「命令名 + key=value」的简单文本，避免在 Lua 里写解析器。
- 路径与文件名一律纯英文；读文件用 `LrFileUtils`；用户目录用 `LrPathUtils.getStandardFilePath("home")`（`os.getenv` 不可用，实测）。
- 日志写 `LrLogger`（实际位置 `%LOCALAPPDATA%\Adobe\Lightroom\Logs\LrClassicLogs\*.log`，实测）。

## 6. Python 服务

- 官方 `mcp` 库（先试 2.x 的 `MCPServer`，不行退回 `mcp>=1.30,<2` 的 `FastMCP`，**待验证**）；stdio 传输，**stdout 不能打印任何东西**，日志写文件。
- 目录：`server/lightroom_mcp/`（`server.py` 工具、`bridge.py` HTTP 队列与认证、`previews.py` 图片与直方图、`doctor.py` 自检）+ `tests/`。
- 依赖：`mcp`、`pillow`。环境：用户本机用 conda 环境 `lrmcp`；配置里写解释器**绝对路径**。朋友机器的做法见第 8 节。
- 超时：插件取任务最长等 10 s（实测：LrHttp 的超时是「每阶段」，实际约为设定值的 2 倍，设 15 s）；预览任务设 30 s 超时。

## 7. Claude 与 Codex

- 只用标准 MCP（stdio）。Claude Code：`claude mcp add`；Codex：`~/.codex/config.toml` 的 `[mcp_servers.lightroom_mcp]` 或 `codex mcp add`（服务名用下划线）。
- Claude 桌面版配置文件位置因 MSIX **可能被重定向**，安装脚本要从设置里的「编辑配置」取真实路径（**待验证**）。
- Codex 能否把 MCP 返回的图片传给模型：**待验证**（搜索显示 2025-10 有修复）。备用：服务把预览存成文件并返回路径，由客户端用自带看图功能打开，做成一个开关。
- v1.0 完成后 Claude、Codex 各跑一遍；Codex 要等用户装好才能测。

## 8. 一键安装与自检（给朋友用）

| 步骤 | 说明 |
|---|---|
| 检查 | Windows、Lightroom Classic 是否安装、版本（`LrApplication.versionTable()` 报 15.x） |
| 装插件 | 复制到 `%APPDATA%\Adobe\Lightroom\Modules\`（自动加载，实测路径）。**必须由用户在普通 PowerShell 里运行**（Claude 启动的 shell 会把 AppData 写入重定向） |
| 装 Python 环境 | 用户本机：conda `lrmcp`。朋友：需要 Python 3.11+，安装脚本在 `~/LrMcp/venv` 建环境并装 `mcp`、`pillow`（**待定：是否可以要求朋友先装 Python**） |
| 登记 | 自动对 Claude Code / Codex 执行 add（找得到哪个就登记哪个） |
| 自检 `lr_doctor` | Lightroom 在运行吗？插件已加载吗（`status` 能返回）？端口被谁占？口令文件在吗？依赖齐吗？MSIX 重定向陷阱？Claude/Codex 已登记吗？每项给中文结论与处理办法 |

## 9. 测试与验收

- Python：`pytest` 单元测试（认证、Host/Origin 规则、直方图数字、单实例）。
- Lua：通过开发通道在测试目录 `ceshi1` 上跑脚本；只动 `ceshi` 目录里的照片。
- v1.0 验收：
  1. 在测试目录选一张 RAW、一张 JPEG，`lr_list_selected`、`lr_get_develop`、`lr_get_preview` 都返回正确内容；
  2. Claude 能说出「这张哪里偏暗/偏黄/过曝」且与直方图数字一致；
  3. Lightroom 里没有任何参数被改变（逐项比对）；
  4. 关掉 Python 再打开，不用重启 Lightroom 就恢复；
  5. 错口令、带 Origin、端口被占用都有正确的拒绝/提示；
  6. `lr_doctor` 在「Lightroom 没开」「插件没加载」两种故障下给出正确诊断。

## 10. 之后的版本（接口已实测的部分先记在这里）

| 版本 | 要点（来自实验） |
